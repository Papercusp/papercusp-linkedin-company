# LinkedIn company-page provider

This package implements company-page public text posts and reads of posts authored by the explicitly configured `organizationId`. It uses the Posts API pinned to `202609`. It declares no comments, replies, media upload, personal-profile posting or organization auto-selection. The separate `linkedin` package continues to serve personal-profile posting.

**Partner approval pending.** The shipped `verification.blockedOn` refuses OAuth, identity lookup, reads and posting before any network call. The adapter also refuses by name with `linkedin-company:partner_approval_required`; a source config or invocation argument cannot clear it. Avi submits the [prepared application](/reports?sel=rpt_40655de8-8bd0-440c-bd9d-e5f6052943f3). No application has been submitted by this package.

After approval and data-flow review, the separate `linkedin-company` app registration needs both Sign In with LinkedIn using OpenID Connect (`openid`, `profile`) and Community Management (`r_organization_social`, `w_organization_social`). Identity comes from the documented `/v2/userinfo` `sub`, rather than the first organization or ACL row. The configured Page id is a separate resource; LinkedIn enforces the connected member's Page role. The host stores and injects credentials and requests reauthorization on expiry. No personal registration, secret or grant is shared implicitly.

Before removing the blocker, review actual Member Data handling: host connection identity persistence, social-record storage, event routing, search/embedding ingestion and any model-service transfers against the approved application and LinkedIn terms. This package sets no default destination policy. An absent default is not proof that the full host data flow meets those terms. Approval and compliance have not been established.

Reads follow validated vendor next-page links, including short pages with a next link. Each completed cursor retains observed post versions; the next pass rescans the authored collection and emits new or modified versions. This avoids treating an offset or timestamp as a complete snapshot when posts shift during pagination. The cursor refuses malformed, cross-organization or off-host pagination and histories above 10,000 observed versions per scan. That bound produces a named failure, never a silently complete partial history. The API is an authored-post collection, not an incoming-comment inbox or a deletion feed.

Publishing makes one request. Transport failure, 409/5xx or a successful response without a valid server post URN stays unconfirmed and is not retried inside the package. Host account consent, social outbound checks, quotas and audit receipts still apply. No numeric company quota is copied from the personal-profile API; approved application limits remain an activation prerequisite.

Verification uses offline HTTP fakes and the unchanged SDK conformance kit, including an isolated hypothetical approved manifest. **Live verification pending.** Offline approval controls grant no real access. The installed shipped daemon must refuse the actual blocker. No vendor calls are made by tests.

Reuses the provider descriptor, host OAuth/identity, owner-blocking rails, SDK-generated standalone daemon, canonical social records and existing social outbound dispatch. Primary contracts checked 2026-10-17: [Posts API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/posts-api), [OpenID Connect](https://learn.microsoft.com/en-us/linkedin/consumer/integrations/self-serve/sign-in-with-linkedin-v2), [Organization access control](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/organization-access-control-by-role). No organization ACL endpoint is used as the account identity.
